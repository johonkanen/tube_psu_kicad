# Findings: 03 isolated measurements  (reviewer: Claude Opus 5.5, 2026-11-24, commit 3e1e31e)

## Summary
The isolated measurement chains (AD1 / ISO1 heater side, AD2 / ISO2 420 V side) are electrically the 5.1 circuit:
same values, same placement (identical positions to the 5.1 board), and the ISO1 / ISO2 parts change from Si8661BD
to CA-IS3761LW with the same pinout, default-low outputs and the same timing class. I found no blocker for ordering.
Slots (now 1.5 mm, stage 13b) give 12.58 mm (ISO2) and 8.88 mm (ISO1) surface paths, which is at least the 11.1 / 8.2 mm
required. `check_domains.py` reports 0 pairs below their limit, and no accepted exception involves this part.
The open point is the isolator safety rating. The newest wide-body datasheet revision I could fetch (Revision F) rates
the SOIC16-WB at **VIOWM 600 Vrms / VIORM 849 Vpk**. The repository says 1000 Vrms / 1414 Vpk (that number is from
the 2019 revision). The rating has reinforced certificates (TUV 61010-1 / 62368-1, CQC), but **VDE 0884-11 is still
"Pending"**. The margin against the 552 Vrms ISO2 barrier is 8 %. The documents need correcting (should fix).

## Findings (ranked, most severe first)

### F1 Isolator rating in the documents is the 2019 value; VDE certificate for the WB part still pending; README names the old parts
- Severity: **should fix**
- What is wrong: the board parts are ISO1 / ISO2 = **CA-IS3761LW** (LCSC C528659) and U11 = CA-IS3721HW (`rv sch ref ISO1,ISO2`, `rv bq fp`). CHANGES_5_2.md:113 and the `lib/jlc_parts_next.csv` note for ISO1 / ISO2 give "VIOWM 1000 Vrms / VIOTM 7070 Vpk (WB)". The newest WB datasheet revision I could fetch (CA-IS376x **Revision F**, §7.6 p 7) gives **VIOWM 600 Vrms (TDDB) / VIORM 849 Vpk / 849 VDC** for the W package, against 552 Vrms / 778 Vpk needed for ISO2 (8 % / 9 % margin). Its §7.7 says "**VDE (Pending)**". Reinforced 600 Vrms is certified by TUV (CB JPTUV-111116 / DE 2-027880, AK 50474786 0001; EN/IEC 61010-1 and 62368-1) and CQC20001251466 (SOP16-W), and UL 1577 is file E511334. CHANGES "Open questions" 2 still calls everything "pending". The repository's own position on the 8 mm package creepage against the 11.1 mm board rule is missing. kicad_next/README.md:2271 ("Primary ↔ UART island (Si8621BD)"), :2301 ("ISO1 / ISO2 Si8661BD, UART Si8621BD") and :2304 ("Check that the Si8661BD reinforced rating … covers 552 Vrms") still name the 5.1 parts.
- Evidence: `pdftotext` of Rev F (https://tellur-el.ru/upload/iblock/62f/u8in8xea19pzzmjint2f18t1yawnrsfs.pdf) p 7–8. The 2019 LCSC datasheet for C528659 (https://datasheet.lcsc.com/datasheet/pdf/a3d31674f5dd929b2ba9319168218955.pdf, §6.6: VIOWM 1000 Vrms W; §6.7: every certificate "申请中"). The v1.06 2023-09-13 datasheet with VDE certificate 40052786 covers only the SSOP16 "B" parts (ordering table lists LB/HB only, VIOWM 400 Vrms).
- Smallest fix: correct CHANGES 3a, the parts-table note and README "Working voltages" / "Consequences" to: CA-IS3761LW, VIOWM 600 Vrms / VIORM 849 Vpk (Rev F), reinforced per TUV / CQC certificates, VDE pending. Add one line saying that the package's 8 mm MG I surface is covered by the component certification and the 11.1 mm rule applies to the PCB (slot). Get the current Chipanalog datasheet / VDE certificate before series use. Note that the "ISO_GND may float" 16 mm alternative (≈ 800 Vrms) would exceed 600 Vrms, so that alternative would also need another isolator. Si8661BD (5.1) has the same 600 Vrms reinforced 62368-1 rating (206330A p 1/27) but a VDE 0884-10 certificate, so 5.2 is equal on rating and slightly weaker on certification.
- Confidence: medium-high. The rating figures are from the fetched datasheet. Chipanalog's own site was not reachable (404), so a revision newer than F with a VDE number for the LW cannot be excluded. A Chipanalog download or a VDE certificate search for "CA-IS376x" would settle it.

### F2 R68 (12.1 kΩ 1206 bleeder on the −100 V bias rail) dissipates 0.55 W in a 0.25 W part (outside this checklist, lead verified)
- Severity: **should fix** (rating exceeded on paper; same as 5.1)
- What is wrong: R68 sits between ISO_GND and `-100V BIAS` (`rv sch ref R68`). The rail is 78.5–82.8 V (simulation/flyback/FLYBACK_DESIGN.md:41, :318): P = 81.3² / 12.1 k = **0.546 W** (0.57 W at 82.8 V). The part is C247391, 1206W4F1212T5E: LCSC page (https://www.lcsc.com/product-detail/C247391.html) gives **250 mW, 200 V**, i.e. 2.2× overload. 5.1 has the same part (`rv sch51 ref R68`: 12.1K 1206).
- Evidence: the two commands above plus the calculation.
- Smallest fix: (checklist 01 decides) a 2512 / 1 W part needs a footprint change. Within the 1206 footprint, raise the value (e.g. 33 kΩ → 0.20 W) if the flyback cross-regulation allows: the flyback simulation uses the 12.1k bleeder (simulation/flyback/flyback_sim.py:25), so re-run it. Alternatively put two 1206 in series in the existing space.
- Confidence: high for the arithmetic and the rating. The bench survival of 5.1 suggests the real rail or the board temperature is tolerable, but this was not measured.

### F5 MIC5205 output capacitor is a 2.2 µF X5R 0603 ceramic

- Smallest fix: none needed for the acceptance bar. If the bench shows ripple on AD2_3V3 / HT 3.3 V, use a 4.7 µF 0603/0805 or add 1 Ω in series.
- Confidence: medium.

### F6 Dead isolated side reads as 0 V; ISO2 outputs are undetermined while AD2_3V3 is below UVLO
- Severity: **note**
- What is wrong: with side 2 unpowered, ISO1 / ISO2 pin 7 (SDATA towards the FPGA) is driven to the default **low** (Rev F truth table), so the FPGA reads code 0 = "0 V heater / 0 V on 420V", which cannot be told apart from a real 0 V. Conversely, while 5V_ISOL ramps and AD2_3V3 < 2.375 V, the ISO2 outputs (DRV6 INA / INB / DIS) are "undetermined" (Rev F p 17). DRV6 is held off then only by its own UVLO and internal input pull-downs. The topology is the same as 5.1 (Si866x has the same rule).
- Smallest fix: firmware: do not use AD1 / AD2 data before the heater / flyback is known to be up (e.g. require a non-zero code or a timeout). Hardware: none.
- Confidence: medium (DRV6 UVLO order is checklist 02).

## Bring-up notes (F1 / F2 of the checklist)
- AD2 without high voltage: leave the 420V rail unpowered and power the flyback (5V_ISOL). Then (a) put a 30.0 V bench supply on the 420V node (C19 / C30 / P400V terminal): V(CUK_CAP_MEAS2) = 30 × 15k / 3.015 M = 0.1493 V, Vout = 0.150 V, code = 0.150 / 3.3 × 4096 = **186**. Or (b) inject 1.000 V at CUK_CAP_MEAS2 (R38 pad 1) through ≥ 10 kΩ: Vout = 1.005 V, code ≈ **1247**. Expected 24.8 codes per 1 V on the 420V node at 30 V.
- AD1: feed the 6V3 output terminals from a bench supply (powers V3, AD1, ISO1 side 2): 5.00 V → 2.267 V → code **2813**; 6.30 V → 2.856 V → **3545**; 7.28 V = full scale. Below ≈ 3.95 V the reading is wrong (V3 in dropout, VA = reference falls); below ≈ 3.05 V ISO1 side 2 is in UVLO.
- Sequence: AD1 / ISO1 side 2 live only with the heater output (6V3 ≳ 3.05 V for ISO1, ≳ 3.95 V for a valid AD1 reading); AD2 / ISO2 side 2 live only with 5V_ISOL (flyback). Before that, HT_SDATA / CUK_SDATA sit at the default low → the FPGA reads 0x000.
